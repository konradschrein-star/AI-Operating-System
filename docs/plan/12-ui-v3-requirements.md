# 12 — UI v3 Requirements

Numbering: `U#` functional, `NFU#` non-functional. These extend (do not replace) R1–R22 from `01-requirements.md`; R-series work already shipped stays binding. Every U maps to exactly one phase in `15-ui-v3-phases.md`. "Testable" means the reviewer can verify with a command, a curl, a screenshot, or a DB query — each requirement names its check.

## A. Read-side API (forge-control) — Phase 300

- **U1 — Chat↔project linkage.** `POST /api/projects` accepts optional `origin_chat_id` (uuid), stored in `project.metadata.origin_chat_id` at the ROUTE layer (routes/projects.ts builds metadata; db/projects.ts untouched). Test: create a project with the field, `GET /api/projects/:id` echoes it in metadata.
- **U2 — Linkage resolution.** A route-local resolver maps chat→project: primary = `metadata.origin_chat_id`; fallback = bounded scan of the chat's thread for project UUIDs returned by `POST /api/projects` tool_results. The response carries `link_source: "metadata" | "thread_scan"` — the fallback is visible, never silent. Unlinked chats resolve to `project: null`, not an error. Test: curl a linked chat and a plain chat.
- **U3 — Rail rollup.** `GET /api/chat` (list) gains, per chat that resolves to a project: `project_id`, `tasks_done`, `tasks_total`, `project_status`. One query for the whole page of chats (no N+1: single grouped query over tasks by project_id, route-local SQL). Test: curl list; verify counts match `GET /api/projects/:id` task statuses; `EXPLAIN` shows one aggregate pass.
- **U4 — Team endpoint.** `GET /api/chat/:id/team` returns the scoped tree: `{ manager: Node, workers: Node[] }` where each worker carries `subagents: Node[]`. Node = `{ id, kind, role, model, status, tokens: {input, output, cache_read, cache_creation, total}, working_ms, started_at, settled: bool, description? }`. Workers = runs with `metadata.project_id = <linked project>`; manager = the chat run itself; sub-agents from `metadata.subagents_v2` / thread fallback — REUSING agents.ts phase-1/2 logic (frozen elapsed, agent_kind, sub-agent rollup), not duplicating it: extract shared helpers within routes/agents.ts and import from there. Test: curl against this very project's chat; tree shape validates; a settled worker's `working_ms` is identical across two curls 10s apart.
- **U5 — Working-time definition.** `working_ms` = sum of gaps between consecutive thread events where gap ≤ 120s (gaps > 120s count as idle: queue wait, stuck, awaiting input); for running nodes add `min(now − last_event_ts, 120s)`. The 120s cap is a named constant with a comment, documented in `13-ui-v3-architecture.md §4`. Settled nodes computed once (frozen). Test: unit check script with a synthetic thread (known gaps → known sum); curl-twice frozen check.
- **U6 — Plan endpoint.** `GET /api/chat/:id/plan` returns `{ phases: [{ round_base, title?, tasks: [{id, round, role, title, status, tier, deps: []}], doc_path? }], docs: [name] }` — tasks grouped by hundreds-block of `round`, `deps` derived as "every task in a lower round" (the current engine's implicit ordering, made explicit for the graph model). `GET /api/chat/:id/plan/doc?name=<file>` streams a markdown file, path-restricted to `<workspace_dir>/docs/plan/` with traversal rejected (resolved path must stay under the plan dir; 400 otherwise). Test: curl both; attempt `name=../../etc/passwd` → 400.
- **U7 — Secret request read model.** `GET /api/secrets` list exposes, for pending items, `for_konrad`, `note` (the agent's request text), and additive `requested_by_run_id` if provided at `mark-pending` time. Additive only — existing clients unaffected. Test: mark-pending with a note, curl list, fields present; existing secret flows still pass.
- **U8 — Capabilities feature-detection.** `GET /api/capabilities` returns `{ control_plane: { message_into_session: bool, resume_finished: bool, stop: bool, terminate: bool } }`, all `false` until engine-v2-research-lane implements the vault contract (they flip flags as they land endpoints). The UI reads this once per session and renders unavailable controls disabled-with-reason. Test: curl returns all-false today; UI shows disabled controls with tooltip, not hidden, not silently no-op.

## C. Right panel v3 — team zone (Phase 500)

- **U14 — One panel.** The right sidebar's two halves (AgentActivity + LiveProjectsBody) are replaced by a single `ChatTeamPanel` with two zones, always scoped to the open chat; zero panel-local selectors. SidePanel tab structure may remain for Files (untouchable) vs Team. Test: screenshot; code has no project/manager selector state in the panel.
- **U15 — Team tree.** Top zone renders U4's tree: manager row (model shown) at top; workers indented one level; sub-agents indented two. Every row: role, model, total tokens, working time. Running rows tick (client interpolation between polls is allowed for running rows only); finished rows show tokens + model, NO time. Status dots: blue running, gray planned/queued, green done (token colors: info/textMuted/ok). Test: screenshot against a live project chat, dark + light; a finished row shows no time.
- **U15a — Amendment to U15's time rule (ratified round 506).** U15's clause "finished rows show tokens + model, NO time" is **superseded**: *every* row shows its working time; a settled row shows it **frozen** (`settled_at - started_at`, byte-identical at any clock), a running row ticks. The original text stands above unedited as the record of what was asked.
  - *Why.* U15 and the phase-500 project brief contradicted each other. Definition of Done #1 reads: "a settled run (completed/failed/cancelled) shows a FROZEN duration (settled_at - started_at). Only live runs tick. **No exceptions anywhere in the panel.**" The brief is the governing contract for this phase, and it requires the number U15 forbade.
  - *Why the brief is also the better answer.* Konrad's complaint was that finished agents' clocks "are still growing even though they are done" — the defect is motion, not presence. "How long did the builder take" is the question a finished row exists to answer; blanking it is information loss, and the number was already one hover away in the row's `title`, which means the panel was hiding data it had.
  - *What this replaces.* Rounds 502–505 shipped an unratified middle case — settled **manager** rows showed a duration, all other settled rows showed "—" — which satisfied neither document. Round 505's adversarial review (finding #5) called it out and asked for a ratification or a removal. This is the ratification; the special case is gone, and `TeamRow.tsx` now has no `isManager` branch in its time path.
  - *Test (replaces U15's "a finished row shows no time").* A finished row shows a duration, that duration is byte-identical when the DOM is sampled at t and t+12s, and its cell carries `data-frozen="true"`; a running row's cell carries `data-frozen="false"` and advances. `docs/plan/artifacts/phase500/team-frozen.cjs` asserts exactly this. Structural guarantee: settled rows render `FrozenTime`, which does not import `useTick` and therefore cannot subscribe to a clock.
- **U16 — Frozen truth preserved.** Settled rows never tick — same guarantee as R1–R6, now in the new panel. Test: DOM sampled at t and t+12s, settled cells identical (reuse phase-1 `frozen-dom.cjs` approach against the new panel).
- **U17 — Hover controls.** Hovering any row reveals a red X (terminate/dismiss) and a stop button. CSS-only reveal (opacity/visibility on `:hover`/`:focus-within`) — no React state on hover. Wiring: dismiss uses the existing dismissal-persistence mechanism; stop/terminate call control-plane endpoints when `capabilities` allow, else render disabled with tooltip "engine support pending". Destructive actions (X on a running row) require a confirm step. Test: hover screenshots; profiler shows zero re-renders on hover; with all-false capabilities the buttons are visibly disabled.
- **U18 — Finished sub-agents persist.** Finished sub-agents stay listed under their parent (until dismissed via X). Test: screenshot of a settled project chat showing done sub-agents.
- **U19 — Empty state.** A chat with no linked project and no agents shows an intentional empty zone (short muted line), not a spinner, not an error. Test: screenshot.

## D. In-chat navigation + worker-chat legibility — Phase 600

- **U20 — Drill-in navigation.** Clicking a team row (or, later, a Kanban phase) opens that agent's transcript in the MIDDLE surface. A back button at the top, animated (CSS transition — no animation lib), pops one level. Navigation is a stack: manager → worker → sub-agent, always walkable back to the manager chat. Header of the drilled view shows who you're looking at (role + model or phase doc name). Test: Playwright walk down two levels and back; screenshots.
- **U21 — Existing agent-view reuse.** The drill-in builds on ChatSurface's existing `agentViewFrom` backtrack mechanism rather than a parallel system — one navigation stack, one source of truth. Test: code review; no duplicate state.
- **U22 — Orientation strip.** Any worker/sub-agent transcript view pins a strip at top: role + model, task title/round/phase, plain-language "currently: …" (from `metadata.current_activity`), and plan position ("phase 500 of 15-ui-v3-phases; next: 600"). Derived from existing wire data only. Test: screenshot on a live worker.
- **U23 — Readable transcript.** In worker/sub-agent views, tool calls collapse to a one-line human summary (tool + argument gist + outcome), expandable to raw payload — extending the existing `ToolCallRow` pattern, not forking it. The agent's prose renders as the primary layer. Test: screenshot of a raw session before/after; expanding shows full payload.
- **U24 — Story-so-far digest.** Sessions with > ~50 thread entries show a collapsed digest at top derived from existing data (task brief, phase, last N assistant prose snippets, counts of tool calls/errors). NO new LLM pipeline; if derivation is judged insufficient during build, the builder documents exactly what's missing in `docs/plan/artifacts/phase600/digest-gap.md` instead of inventing plumbing. Test: open a 200-entry session; digest present and honest.

## Non-functional requirements

- **NFU1 — Tokens only.** Zero hardcoded colors; every new style uses `app/tokens.ts` CSS vars; both themes verified per phase. Test: `grep -rnE "#[0-9a-fA-F]{3,8}\b" <touched files>` clean (excluding tokens.ts itself).
- **NFU2 — Hover perf non-regression.** No hover path introduces React state changes or expensive mounts; tooltips/lineage use native `title` or CSS reveals. The deferred phase-1300 protocol will measure the new panel — v3 must not hand it a regression. Gate per UI phase: profiler sample during a 10s hover sweep shows zero component re-renders attributable to hover.
- **NFU3 — Poll budget.** The chat surface's total polling load must not exceed today's (chat list 8s, detail 3s/20s, agents 4s). New endpoints (team/plan) replace the panel's old polls rather than adding to them; one team poll and one plan poll per open chat, ≥5s intervals, paused when the panel is hidden. Test: network tab audit, request counts per minute before/after.
- **NFU4 — Additive API.** No endpoint removed or reshaped; new fields additive; old clients keep working. `/api/projects/managers` stays functional even though the web app stops calling it. Test: curl old endpoints, shapes unchanged.
- **NFU5 — Forbidden files untouched.** `git diff --name-only` per phase contains none of: project-tick.ts, cc-runner.ts, executor.ts, db/projects.ts, FileExplorerPanel*, VaultFileList*, routes/files.ts. Reviewer runs the diff check every phase.
- **NFU6 — Hard errors, no silent fallbacks.** Failed team/plan fetches render an inline error state (muted, explicit) — never stale data presented as fresh, never an empty state masquerading as "no agents". `link_source: "thread_scan"` renders a subtle "linked heuristically" marker. Disabled capabilities render disabled, not hidden.
- **NFU7 — Build gates.** `npx tsc --noEmit` clean in both repos and `pnpm build` green in forge-control-web at the end of EVERY phase, not just deploy.
- **NFU8 — No new runtime deps** without a one-line justification in the phase plan; animation via CSS only; markdown via the existing react-markdown stack. (`@xyflow/react` explicitly NOT added this project — reserved for the future graph phase.)
- **NFU9 — Worktree discipline.** All build-phase work inside this worktree; /opt/forge-ai-os touched only in Phase 900.

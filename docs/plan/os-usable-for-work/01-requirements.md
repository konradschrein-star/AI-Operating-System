# 01 — Requirements: os-usable-for-work

Every requirement is numbered, testable, and mapped to **exactly one** phase. The phase column is
authoritative; `04-phases.md` repeats the mapping and the two must agree. A requirement with no test
is not a requirement, it is a wish — if you cannot write the assertion, escalate rather than
implement.

**Reading the tables.** *Test* is the assertion a reviewer runs. *Fails when* names the concrete
condition that makes the requirement RED — written so that a reviewer can try to break it rather than
confirm it.

## Lane 1 — Vault + Memory

### Phase 1 — Vault write path and index truth (workstream `vault`)

| ID | Requirement | Test | Fails when |
|---|---|---|---|
| **R1** | `GET /api/vault/file?path=<vault-relative>` returns `{path, content, sha256, mtime_ms, bytes}` for any non-dot `.md` under the vault. | `curl` a known note; assert `content` equals `readFile` output byte-for-byte and `sha256` equals `sha256sum` of that content. | Content is trimmed, re-encoded, newline-normalised, or the hash is computed over anything other than the exact bytes returned. |
| **R2** | `PUT /api/vault/file` accepts `{path, content, base_sha256}` and writes only if the file's current sha256 equals `base_sha256`. | PUT with the correct base → 200 and the new bytes on disk. | A PUT without `base_sha256` is accepted, or a mismatched base is accepted. |
| **R3** | On sha mismatch the API returns **409** with `{error, current_sha256, current_content}` and **does not write**. | Read a note, mutate it on disk out-of-band, PUT with the now-stale base; assert 409 **and** that the on-disk bytes still equal the out-of-band version. | The write lands, or the 409 body omits the current content (the UI then cannot show a diff). |
| **R4** | Every successful `PUT` writes a snapshot of the **prior** content to the snapshot store before the new bytes land. Snapshots live **outside** the vault at `/opt/ai-os/vault-snapshots/<YYYY-MM-DD>/<flattened-path>.<epoch-ms>.md`. | PUT a change, then read the snapshot back and assert it equals the pre-PUT content. | The snapshot is written after the file, written inside the vault (polluting it), or skipped when the note is large. |
| **R5** | A failure to write the snapshot **aborts the PUT** with 500 and leaves the note untouched. | Make the snapshot directory unwritable (`chmod 000` on a temp store), PUT, assert 500 and unchanged bytes. | The PUT proceeds "best effort" — the undo guarantee is then a decoration. |
| **R6** | The note write is atomic: write to a temp file in the same directory, `fsync`, then `rename`. | Grep the implementation for `rename`; assert no code path calls `writeFile` directly on the destination path. | An in-place write exists, so a crash mid-write truncates a note. |
| **R7** | `PUT` with `content` that is empty or whitespace-only is rejected with **400** and the file is unchanged. | PUT `{"content":""}` and `{"content":"   \n\n"}`; assert 400 both times and unchanged bytes. | Either is accepted. This is the single accident the append-only contract existed to prevent. |
| **R8** | There is **no** `DELETE` verb and no verb that removes, renames or moves a note. | `grep -n "\.delete\|unlink\|rename(" forge-control/src/routes/vault.ts` — the only `rename` is the atomic-write one in `lib/vault.ts`. | Any delete/move/rename route exists on the vault surface. |
| **R9** | Path resolution for the new verbs reuses the existing `resolveInVault()` guard: traversal rejected, any dot-segment rejected. | Table test: `../etc/passwd`, `/etc/passwd`, `.obsidian/app.json`, `Daily/../../x.md`, `.trash/x.md` → all rejected; `Daily/2026-08-18.md` accepted. | Any of the five rejects is accepted, or the new verbs duplicate the guard instead of reusing it (two guards drift). |
| **R10** | Only `.md` files are readable and writable through these verbs. | `GET`/`PUT` `_Attachements/x.png` → 400. | A non-`.md` path is accepted. |
| **R11** | The pre-existing verbs `POST /append`, `POST /note`, `GET /daily` behave **identically** to before this project, proven by their existing tests plus a byte-level before/after on a scratch daily note. | Run the existing suite; add a characterisation test that appends to a fixture note and diffs the result against a committed golden file. | Any behavioural change to append-or-create, however "harmless". |
| **R12** | `GET /api/memory/index-health` returns a three-way reconciliation: files on disk, rows in `hcp.knowledge_note` (split by `created_by`), distinct `source_path` in `content_forge.knowledge_embeddings` — plus a `discrepancies[]` array where every entry carries `{path, in_disk, in_registry, in_embeddings, reason}`. | Call it live; assert `disk_files == 284` (or whatever `find` reports at the time, computed by the endpoint itself, not hardcoded) and that **every** discrepancy has a non-null `reason`. | A discrepancy is listed with `reason: null` or `"unknown"` — an unexplained gap is the defect this endpoint exists to abolish. |
| **R13** | `index-health` classifies each embeddings-side absence into one of: `excluded_extension`, `empty_file`, `frontmatter_only`, `stale_row_file_missing`, `unexplained`. The count of `unexplained` is a headline field. | Against today's vault, assert `excluded_extension = 15`, `empty_file = 10`, `frontmatter_only = 1`, `stale_row_file_missing = 1`, `unexplained = 0`. | Any file lands in `unexplained` without the endpoint saying so loudly, or the classifier hardcodes today's counts instead of deriving them. |
| **R14** | Stale embedding rows (a `source_path` with no file on disk) are **reported** by `index-health` and removable by an explicit `POST /api/memory/index-health/prune`. Pruning is never automatic. | Assert `Coach/log.md` appears as `stale_row_file_missing`; assert no tick or startup path calls prune. | Prune runs on a schedule, or on read. Silent deletion of index rows is how a "self-healing" system eats data. |
| **R15** | `GET /api/memory/counts` returns a **labelled envelope**: every integer field's name states its unit and its source table. Minimum fields: `vault_files_on_disk`, `vault_notes_indexed`, `agent_notes`, `embedded_files`, `embedded_chunks`, `measured_at`. | Assert every top-level integer key matches `/^(vault|agent|embedded|excluded|stale)_/` and that `measured_at` is within 60 s of now. | A bare `all` field survives, or any count is returned without a sibling that says where it came from. |
| **R16** | The old `all` field either disappears or is renamed to something unambiguous. If any consumer still needs the union, it is named `notes_all_sources` and documented as a union. | `grep -rn '"all"' forge-control/src/routes/memory.ts forge-control-web/app` returns no memory-counts usage. | `all` survives as-is and the surface keeps rendering an unlabelled 482. |
| **R17** | Category counts are **either** made honest **or** removed. Honest means: derived from a rule that can produce a non-zero number against the real vault, and the rule is documented in the response (`category_rule` field). Removed means: the chips are gone and the reason is in the commit message. | Whichever branch is taken, assert no chip can render `0` for a category the vault demonstrably contains. If `project` renders 0, assert a test proves the vault contains no project notes under the stated rule. | Five chips still show a structural zero because `inferCategory()` matches tags the vault does not use. |
| **R18** | An `obsidianUri({vaultName, vaultRelativePath})` helper exists in a **shared, unit-tested module** and produces `obsidian://open?vault=<enc>&file=<enc>`, percent-encoding spaces, `&`, `#`, `?`, `+` and non-ASCII correctly. | Table test including `AI OS/Specs/Directory + Business Plan Hub — Business Model.md` and `40_Life Knowledge/x & y.md`; assert round-trip through `decodeURIComponent`. | The path is passed through `encodeURI` (which leaves `&` and `#` intact and breaks the link), or `+` is treated as a space. |
| **R19** | The vault name is **configuration, not a guess**: `OBSIDIAN_VAULT_NAME`, defaulting to the basename of `OBSIDIAN_VAULT_DIR` (`obsidian-vault`), exposed read-only on the API so the UI can display it. | Assert the default resolves to `obsidian-vault`; assert setting the env changes the emitted URI. | The vault name is hardcoded anywhere, or the `.md` extension is stripped from `file=` (Obsidian accepts both, but the helper must be deterministic and tested for whichever it picks). |
| **R20** | `index-health`, `counts` and the vault verbs **hard-error**. No `catch {}` that returns a default, no `?? 0`, no `|| []` standing in for a failed query. | `grep -n "catch\s*{[^}]*return\|?? 0\||| \[\]"` over the touched files; every catch must rethrow or return a 5xx with the message. | Any handler swallows a database error and returns a zero, which is exactly how "it's zero and not eight" happens a second time. |

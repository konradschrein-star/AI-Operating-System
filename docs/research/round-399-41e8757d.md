### 1. Gemini: Default video model is NOT video-capable ✗ WRONG

**Documented claim (02-architecture.md §6.2, line 196):**
> "Default model `gemini-3.6-flash` ($1.50/$7.50 per 1M; video ≈ 300 tok/s standard res)"

**Current reality:** `gemini-3.6-flash` does **NOT support video input**.

**Evidence:**
- **Primary source:** https://ai.google.dev/models
- Gemini 3.6 Flash is described as "balances speed with intelligence for agentic and multimodal tasks" — text/image, not video.
- **Current video-capable models (as of 2026-08-05):**
  - `veo-3.1-generate-preview` (video generation, per-second pricing: $0.40–$0.60/sec)
  - `gemini-omni-flash` (multimodal + video, text pricing $1.50/$9.00 per 1M tokens; video at 5,792 tok/sec ≈ $0.10/sec at standard pricing)
  - `gemini-2.5-flash-native-audio-preview-12-2025` (bidirectional voice/video)

**Impact:** `gemini-qa.mjs` script will fail immediately when given video input to `gemini-3.6-flash`.  
**Action required:** Revise default to `gemini-omni-flash` or confirm Gemini 3.6 should only handle image QA (not video).

### 2. Gemini: Video pricing model is fundamentally wrong ✗ WRONG

**Documented claim (02-architecture.md §6.2, line 196):**
> "$1.50/$7.50 per 1M; video ≈ 300 tok/s standard res"

**Current reality:** Video pricing is **per-second, NOT per-token**.

**Evidence:**
- **Primary source:** https://ai.google.dev/pricing (accessed 2026-08-05)
- **Veo 3.1** (video generation): $0.40–$0.60 per second depending on resolution
- **Gemini Omni Flash** (video + text): 
  - Text input/output: $1.50/$9.00 per 1M tokens
  - Video input: 5,792 tokens/sec for 720p (not the 300 tok/s claimed)
  - Effective cost: ~$0.10/sec at standard pricing if consumed as token stream

**Impact:** Cost model in brief/decision-making is inverted. A 60-second video is NOT "18,000 tokens at $1.50/$7.50 per 1M" but rather a fixed per-second charge or a token burn at 5,792 tok/sec.  
**Action required:** Revise cost calculations in any pipeline briefing that uses `gemini-qa`.

**Documented claim (02-architecture.md §6.3, line 222):**
> "`ask` → `POST https://api.perplexity.ai/chat/completions` (Bearer auth)"

**Current reality:** Sonar Chat Completions API is **deprecated (July 2026)**. Recommended endpoint is Agent API.

**Evidence:**
- **Primary source:** https://docs.perplexity.ai/docs/resources/changelog
  - Changelog entry (July 2026): "Sonar Chat Completions is now Agent API."
- **Deprecation notice:** https://docs.perplexity.ai/api-reference/chat-completions-post
  - At top of Chat Completions docs: deprecation warning pointing to Agent API as replacement.
- **Current recommended endpoint:** `POST https://api.perplexity.ai/v1/agent`
  - Docs: https://docs.perplexity.ai/docs/agent-api/quickstart

**Impact:** Chat Completions may still work (legacy support) but `scripts/perplexity.mjs` should target Agent API for forward compatibility and modern feature set.  
**Action required:** Migrate to `/v1/agent` endpoint; verify response schema matches Agent API contract (see next issue).

### 4. Perplexity: Response fields differ between Chat Completions (deprecated) and Agent API ✗ INCOMPLETE

**Documented claim (02-architecture.md §6.3, line 224):**
> "emit `{ answer, citations, search_results }` from the response fields of the same names"

**Current reality:** Agent API response structure does **NOT include top-level `citations` or `search_results`**.

**Evidence:**
- **Primary source:** https://github.com/perplexityai/api-platform-developers/blob/main/references/response-and-streaming.md
  - Agent API response: top-level fields are `id`, `created`, `model`, `output` (array of output items)
  - **`output[]` contains items with `type`:** `"text"`, `"search_results"`, `"tool_call"`, etc.
  - **`citations` field: does NOT exist at top level in Agent API**
  - **`search_results` field: does NOT exist at top level; instead, output items with `type: "search_results"` contain `search_results` array**
- **Legacy Chat Completions** (deprecated): did have top-level `citations` and `search_results` fields
  - But this API is no longer recommended

**Impact:** `scripts/perplexity.mjs` logic expecting `{ answer, citations, search_results }` will fail or miss data if switched to Agent API without refactoring response parsing.  
**Action required:** Clarify whether brief still wants legacy Chat Completions (for stability) or Agent API (forward-compatible); if Agent API, update response parsing to extract fields from `output[]` items by type.

### 5. Perplexity: Model name and pricing are from deprecated API ✗ OUTDATED

**Documented claim (02-architecture.md §6.3, line 224):**
> "default `sonar-pro` ($3/$15 per 1M + per-request search fee)"

**Current reality:** `sonar-pro` is from the **deprecated Chat Completions API**. Current recommended model is `perplexity/sonar`.

**Evidence:**
- **Primary source:** https://docs.perplexity.ai/docs/resources/changelog (July 2026 entries)
  - Sonar Chat Completions (legacy): `sonar-pro` at $3/$15 per 1M tokens + per-request search fee
  - **Agent API (current):** `perplexity/sonar` at **$0.25/$2.50 per 1M tokens** (10× cheaper) with **no per-request fee**, only per-tool-call fees ($0.0025 for web_search)
- **Primary source:** https://docs.perplexity.ai/getting-started/pricing
  - Breakdown: Chat Completions (legacy) vs. Agent API pricing clearly separated
  - Agent API is the recommended path forward

**Impact:** Cost estimates in project briefs are off by 10–12×. Pipeline cost-benefit calculations using `$3/$15` are severely inflated.  
**Action required:** Update default model name to `perplexity/sonar` and revise cost figures to $0.25/$2.50 per 1M tokens; remove per-request search fee assumption.

# Round 399 — Scout S-A: the real `agy` login flow

Full findings: [`docs/plan/artifacts/os-usable-for-work/phase0/S-A-agy-flow.md`](../plan/artifacts/os-usable-for-work/phase0/S-A-agy-flow.md)
— the path named by the phase-0 brief and consumed by Phase 4 (04-phases.md line 227,
`phase4/agy-flow.md`).

One-line summary: `agy` (now 1.1.14) has no `login`/`auth` subcommand — auth is implicit, a PKCE
flow with a 60s window where a human pastes an authorization code shown on
`antigravity.google/oauth-callback`; absolute path works under `env -i`, bare `agy` does not
(PATH-only, matches the brief). New finding beyond round-1350: on this box **every** `agy`
invocation logs "Using file-based token storage because SSH session detected" — the
`agy-keyring.service` round-1350 built may not be what actually persists Konrad's token in
production, since at least one live pm2 worker inherits the same SSH-flavoured environment. `agy
models` remains the correct fast (~0.3s) non-interactive auth probe: exit 0 = authenticated, exit
1 = not.
